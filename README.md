# USB Bridge

Интернет компьютера → USB → Android → точка Wi‑Fi. Windows-программа работает из распакованной папки. Android-приложения: USB Bridge и WireRoute.

## Скачать и запустить

Откройте [последний релиз](https://github.com/Nikita15313/usb-bridge/releases/latest). Выпуск сочетает **USB Bridge 0.15.7 для Windows** и **WireRoute 3.1.13 для телефона (код323)**. Android USB Bridge остаётся версии **0.15.5**.

1. Скачайте `USBBridge-Windows-0.15.7.zip`, распакуйте целиком и откройте `USBBridge.exe`.
2. Обновите WireRoute на телефоне до 3.1.13 поверх прежней версии. Профили и выбранные приложения сохраняются. Если код323 или более новая версия уже установлены, повторная установка не нужна. Для первой установки Android USB Bridge 0.15.5 и официального Shizuku используйте предыдущий комплект 0.15.5; WireRoute берите из текущего релиза.
3. Подключите кабель, выберите «USB-модем»; если Windows его не видит — «MIDI».
4. Нажмите «Подключить» в USB Bridge на телефоне и компьютере.
5. VPN включается в WireRoute телефона. Раздача включается кнопкой «Включить Wi‑Fi» в USB Bridge.

Другим устройствам нужны имя сети и пароль. Режим «Без VPN» относится к VPN телефона: VPN самого компьютера остаётся частью выбранного источника.

Обновлённый помощник передаёт служебную связь уже открытому USB Bridge сразу после запуска. WireRoute 3.1.13 обрабатывает подключение USB, когда VPN уже включён по Wi‑Fi или мобильной сети. Обычный запуск выполняется кнопкой «Подключить»; отдельный флажок не требуется.

## Рабочий ПК без USB ADB-драйвера

В Windows 0.15.7 кнопка «Подключить» сама выбирает служебный канал: обычный USB ADB либо уже разрешённый доступ через USB-модем. Флажок «Использовать подготовку дома» больше не нужен и не влияет на подключение.

На рабочем ПК выберите на телефоне «USB-модем» и нажмите «Подключить» в обоих приложениях. При первом обращении Android может запросить разрешение этому компьютеру — подтвердите его на телефоне. Через MIDI служебный доступ без USB ADB-драйвера не работает.

Если служебный доступ на телефоне ещё не разрешён, нужен ПК с работающей USB-отладкой. Остановите подключение и откройте «Подключение» → «Служебный доступ» → «Разрешить доступ». Перед изменением показывается отдельное подтверждение. Кнопка «Подключить» сама это разрешение не включает.

Разрешение включает legacy TCP-отладку на порту 5555. Канал не шифруется; доступ защищён ключом компьютера, а порт может быть доступен и через другие сети телефона. Используйте доверенные сети. Нестандартные настройки сетевой отладки не перезаписываются. Для выключения режима используйте «Служебный доступ» → «Отключить доступ» на ПК с работающей USB-отладкой либо настройки отладки телефона.

На рабочем ПК программа обращается только к точному адресу телефона из текущего USB-соединения. Сокет привязан к исходному адресу и индексу USB-интерфейса; чужие адреса по LAN не сканируются. Смена кабельного сеанса, интерфейса или адреса отменяет попытку. Другие ADB-подключения и VPN компьютера не изменяются.

**После перезагрузки телефона Android может отключить служебный доступ.** Тогда разрешите его снова на ПК с работающей USB-отладкой. Обновление программы не отменяет системные разрешения Android. Реальный TCP-канал через USB-модем и комплектный ADB проверены на OnePlus с Android 17/SDK37; проверки .NET проходят на CLR2 и CLR4. Работа именно на рабочем Windows 7 требует отдельного аппаратного теста.

## Обновления

Начиная с USB Bridge 0.15.5 приложение проверяет подписанный файл обновлений примерно раз в 30 секунд, пока программа работает. На Android проверка действует при открытом приложении или активном USB-подключении; после полной остановки приложения Android не гарантирует выполнение каждые 30 секунд. При сетевых ошибках проверки становятся реже и затем возобновляются.

Доступная версия показана внутри приложения. Загрузка начинается по нажатию. Windows предлагает применить обновление после остановки USB-подключения; новая версия запускается из пользовательской папки. Android показывает обычное системное подтверждение установки. Обновления USB Bridge и WireRoute предлагаются в USB Bridge отдельно. Старые версии без этой функции нужно один раз обновить вручную.

Файл `updates/stable.json` подписан RSA-SHA256; открытый ключ закреплён в приложениях. Файлы проверяются по размеру и SHA-256; Android дополнительно проверяет пакет, версию и сертификат приложения. Запросы используют HTTPS. Неподписанный или повреждённый файл обновления не принимается. Для проверки не нужны учётная запись GitHub и токен.

**Совместимость обновления:** WireRoute 3.1.13 сохраняет package ID и исходную подпись. Версию 3.1.9 из старого комплекта не требуется устанавливать перед ним. USB Bridge учитывает установленный versionCode и не предлагает понижение. Настройки и ключи VPN не входят в распространяемые файлы.

## Windows 7 и системный доступ

Целевые системы Windows-программы — Windows 7, 8.1, 10, 11 с доступным .NET Framework. HTTPS-обновления требуют рабочей поддержки TLS 1.2 и доверенных сертификатов в системе. Старые неподдерживаемые системы не объявляются проверенными.

MIDI/USB-сеть и запуск системного помощника — разные каналы. Комплектный `adb.exe` не устанавливает USB-драйвер Windows. При отсутствии такого драйвера версия 0.15.7 автоматически пробует уже разрешённый служебный канал через текущую USB-сеть телефона. Новые системные права Android без разрешения пользователя она не получает. Перезагрузка телефона и некоторые переключения USB на OxygenOS могут остановить помощник или отключить этот доступ.

Не отключайте оптимизацию OnePlus ради этого приложения. Совместимый вспомогательный сервер сохраняет реальные ограничения Android и передаёт связь уже открытому Bridge при запуске. Официальное приложение Shizuku остаётся неизменённым. Происхождение и точечные изменения сервера находятся в `source/third-party/shizuku-helper`.

## Telegram

«Ожидание сети» и «Соединение» означают разные этапы. Версия 0.15.4 исправила уведомление уже запущенных приложений о появлении USB-сети при рабочем системном доступе. Если Telegram уже пишет «Соединение», требуется проверка фактического пути VPN и соединения с сервером.

Раздел «Диагностика» WireRoute показывает состояние системного доступа, USB-сети и выбора установленных вариантов Telegram для VPN. Он не меняет профиль и не включает VPN сам. В 3.1.13 добавлен переход уже включённого VPN с обычной сети на подтверждённый USB-сеанс. Домашняя физическая проверка подтвердила этот переход, новый handshake и обмен, а также Telegram без «Connecting» при выключенных Wi-Fi и мобильных данных телефона. Работа Telegram именно на рабочей Windows 7 требует отдельной проверки на том компьютере и в его сети.

## Исходники и выпуск новой версии

* `source/windows` — Windows Forms, совместимые с .NET 3.5 API.
* `source/android` — Android USB Bridge, SDK 36 / JDK 17+, Gradle wrapper.
* `source/wireroute-next` — текущий Android WireRoute. Производственная подпись настраивается локально в исключённом `keystore.properties`.
* `source/third-party` и `source/licenses` — исходники и лицензии сторонних компонентов.
* `source/third-party/shizuku-helper` — точечные изменения совместимости, сборка и происхождение вспомогательного сервера157.
* `tools/make_update_feed.py` — создание подписанного файла обновления после сборки и проверки артефактов.

Windows: `source/build-windows.ps1`, с локальными reference assemblies .NET 3.5 через `-Net35References`. Android: `gradlew :app:assembleDebug` в ASCII-пути; WireRoute: `gradlew testReleaseUnitTest assembleRelease`. Подпись обновлений и Android-подпись остаются локальными. Сборка с другой подписью не заменит установленное приложение.

Порядок выпуска описан в `tools/RELEASING.md`. В репозитории нет пользовательских VPN-профилей, журналов телефона, закрытых ключей подписи и настроек устройств. Полные уведомления о сторонних компонентах находятся в `source/THIRD-PARTY.md` и `source/licenses`.
