# WireRoute 3.1.6 USB integration

This update is based on the latest 3.1.2 source. The original project was copied, not edited. Its release applicationId and signing identity are retained. Never distribute keystore.properties, signing keys, profiles or preferences with source archives.

USB mode activates only when the user selects this compatible VPN in USB Bridge. API 2 adds an authenticated ContentProvider stream capability scoped to the selected package and current USB session. WireRoute opens /relay?session=N with a ParcelFileDescriptor; the stream speaks the existing Bridge SOCKS5 UDP-over-TCP dialect. Endpoint DNS is resolved on the PC. Each WireGuard peer uses a temporary loopback UDP endpoint; the protected WireGuard socket's actual source port is checked before forwarding. The original endpoint and all key material remain in the encrypted saved profile; only the in-memory runtime endpoint changes.

PLAIN_START_API=1 advertises an explicit package-targeted broadcast, action local.usbbridge.START_PLAIN with long session. The receiver asks Bridge's provider to authenticate this package and the exact live session, and never interrupts desired encryption. Existing VPN consent allows foreground plain USB startup without launching WireRoute's Activity. Missing consent, background-start restrictions and native failures report plain_permission, plain_background and plain_failed respectively. No hidden permission is granted. A heartbeat only refers to the actual running service's session.

HEV is process-global, so plain and split services now share NativeTunnelLease. A failed or delayed bootstrap cannot stop a worker owned by the encrypted session, and cleanup from a previous owner cannot stop a successor. An exited worker must be joined by its original owner before replacement. Plain bootstrap requires controller DOWN and no desired encryption; OFF intent alone is insufficient while native teardown is still running. Plain and encrypted modes both exclude Android shell, Bridge and WireRoute transport UIDs. The plain heartbeat starts after a post-launch native check and is published on the main loop after fresh session, ownership and mode checks; this is worker-health evidence, not an end-to-end internet claim. Native watchdog exceptions stop/report the failed mode instead of silently cancelling all future checks. UsbPlainVpnService's dump exposes cached packet/byte counts and sample age without blocking the Android main thread on a native call.

When the user switches WireGuard off while USB is connected, UsbPlainVpnService in the same package carries ordinary USB internet through hev-socks5-tunnel. Switching on stops that TUN before starting GoBackend. Both modes use the same Android VPN permission, so the user is not asked to authorize a different package on every toggle. Initial setup still uses Android's required VPN consent. USB loss stops the relevant service and does not reconnect WireGuard through mobile data. A relay failure does not silently switch from encrypted VPN to plain USB.

A single Android VPN TUN captures phone applications; USB Bridge, Android shell and WireRoute itself remain transport exclusions. UsbSplitTunnel inspects TCP/UDP socket owners through ConnectivityManager.getConnectionOwnerUid. Selected application UIDs go to WireGuard, other application UIDs go to the plain PC relay via HEV. The saved encrypted configuration and application choices are unchanged. TCP decisions are pinned for the connection, including retransmitted SYN/FIN; a new initial sequence permits a reused tuple to be reclassified. UDP owner lookup uses both endpoints for each datagram. SDK sandbox UIDs follow their owning application. Shell-owned hotspot sockets, system traffic, isolated/unknown owners and packets that cannot be classified safely remain encrypted. Shared port-53 DNS stays on the VPN's resolver while encryption is enabled; app-owned DoH follows the app choice. Fragmented packets currently take the conservative encrypted path. Thus the selected-app distinction is proven for ordinary attributable TCP/UDP flows, not a claim that every system or fragmented packet can be assigned to an app.

The official Java GoBackend remains intact. Its public getBuilder hook returns the real Android TUN to the dispatcher and a packet-preserving Unix datagram link to WireGuard. The native library is rebuilt from the exact 1.0.20260102 wrapper and f333402bd9cb WireGuard core with a local tun.Device adapter; cryptographic code is not modified. Real non-USB TUN descriptors still use the upstream path. The native build script retains BOOTTIME clocks during suspend and 16 KiB ELF page alignment. HEV and WireGuard have separate bounded outgoing queues so a stalled egress cannot block the other. A native HEV watchdog stops a broken split session rather than leaving a connected indicator. Unsupported partial routes are rejected to prevent physical-network IPv6 fallback. USB per-app routing requires Android 10+; ordinary standalone VPN routing retains its earlier minimum Android version.

The service reports started/alive with mode=plain or mode=vpn to Bridge only after creating its TUN. The separate starting event is sent before stopping plain USB; it requires the hotspot to stop sending ordinary PC traffic while encryption starts. WireRoute waits on its worker for wifiBarrierReady=true from the exact selected, connected USB session. Missing acknowledgment or IPC failure stops encrypted startup before the plain phone TUN is removed; the UI asks to update both Bridge apps and retry. Reports include vpnNetwork only for the current, verified, owned VPN network. Plain and stopped reports carry zero. Handles belonging to the previous plain TUN are excluded. Encrypted reports and session teardown are serialized, so an observer cannot send a stale alive after stopped. Failed encryption and cable loss never restore plain USB; explicit OFF does.

The PFD phone datapath needs no Shizuku, root commands, system-server patching or Windows drivers. Some apps also require legacy Android connectivity status: Android 16 ConnectivityService.getActiveNetworkInfo() returns a VPN's underlying network, not the VPN itself. With only a PFD channel and Wi-Fi/mobile data off, this legacy call returns null while real traffic and modern getActiveNetwork() can work. Telegram's official ApplicationLoader.isNetworkOnlineRealtime() uses this legacy check. It is an Android integration limit, not evidence that Telegram is broken.

API2 may offer connectivityNetwork: a real, working USB TestNetwork from an already running, authorized Bridge helper. The helper supplies this network for ordinary hotspot upstream and chooses the current owned VPN as the UID default for legacy connectivity. Both relay VPN services deliberately use setUnderlyingNetworks(null). Declaring the TestNetwork as underlying would propagate TRANSPORT_TEST onto the VPN, and Android tethering's first-test-network selector can then choose the VPN instead of the actual USB upstream. An empty underlying array is also wrong: it explicitly forces legacy connectivity to null. Null retains the UID default without TEST inheritance. Neither service binds its process or encrypted transport sockets to the TestNetwork. If the helper is absent, direct PFD traffic remains available but legacy offline detection cannot be guaranteed fixed. No mobile data or separate Wi-Fi uplink is enabled by this mechanism.

Stock Android hotspot forwarding still needs the helper's elevated system access. Bridge can bind its shell-owned SOCKS gateway to the reported exact VPN network; the main WireGuard transport remains direct USB, preventing recursion. The gateway must fail closed on a missing network and use that VPN's DNS. WireRoute retains exclusions for shell, Bridge and its own UID, and never changes saved profile keys or endpoints. The relay accepts one full-route peer with an IPv4 address or DNS hostname endpoint; unsupported profiles fail explicitly instead of falling back to another network.

The encryption switch controls the phone's WireGuard backend. OFF checks the native backend is DOWN, waits for its service lifetime to finish, then restores plain USB. Android's VPN icon can remain because plain USB also uses VpnService. A VPN already active on the computer remains the PC's source and cannot be disabled by the phone's switch.

Throughput: encrypted datagrams use one PFD write, input is buffered, plain streams use 16/32 KiB copies, and latency-sensitive local sockets disable Nagle buffering. There is no application bandwidth limiter. Bounded session/packet queues protect memory; dropped-queue and unresolved-owner counters are included in the service diagnostic dump. These changes do not alter MIDI hardware throughput or claim a measured maximum transfer rate.

Verification must include two independent app UIDs with different choices, a VPN-only endpoint and a plain-PC-only endpoint, successful allowed paths and failed reverse paths, actual external HTTPS, DNS/UDP, plain restore, and hotspot traffic with no ordinary-PC fallback. A VPN icon or a saved checkbox is not proof of the egress. Instrumentation accepts requireConnectivity=true to assert that the helper network exists but the owned VPN does not inherit TEST, and that no process binding occurred. Legacy connectivity and repeated hotspot selection must also be checked externally. Generated fixture keys and isolated emulator packages are used; no user profiles are required.

Primary references: [Android 16 ConnectivityService](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/heads/android16-release/service/src/com/android/server/ConnectivityService.java), [VpnService underlying network contract](https://developer.android.com/reference/android/net/VpnService#setUnderlyingNetworks(android.net.Network[])), [Telegram ApplicationLoader](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/messenger/ApplicationLoader.java), [owned VPN network UID](https://developer.android.com/reference/android/net/NetworkCapabilities#getOwnerUid()).

Build with the Gradle wrapper, JDK 17+ and SDK 36. Configure private release signing locally in keystore.properties. `-PusbTest` builds an isolated emulator-only package; it must never be distributed as the user's update. Tests generate their own temporary profile and assert the isolated package and emulator before writing data.
